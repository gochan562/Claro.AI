You are refactoring Claro.AI's Hugging Face model cell system.
This is NOT a bug fix. This is an architectural redesign.
The current implementation chooses the Hugging Face AutoModel... class based on the selected task (Text Generation, Question Answering, Translation, etc.).
This approach is fundamentally incorrect because many Hugging Face models can perform the same task while requiring completely different loading classes.
Examples:
Question Answering + Llama-3 → AutoModelForCausalLM
Question Answering + Gemma → AutoModelForCausalLM
Question Answering + Qwen → AutoModelForCausalLM
Question Answering + MSA-4B → AutoModelForCausalLM
Question Answering + T5 → AutoModelForSeq2SeqLM
Question Answering + BERT-SQuAD → AutoModelForQuestionAnswering
The task is the same, but the loader is different.
